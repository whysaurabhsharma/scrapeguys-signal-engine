2026-11-20. Documented gap, not collected data.

## Finding
Going's problem is whether a fare it alerted on is still bookable at that price. The question can only be answered at the moment of booking, by a dated itinerary search. A plain, polite client cannot reach that answer on any source measured. Four of seven route pages returned content, but these are static "from" fare pages, not a priced search for an alerted itinerary. Expedia answered HTTP 429 on the first request. Google Flights, the metasearch most fare checks start from, is disallowed by robots.txt. GDS and NDC, which Going's VP of Engineering posting names, are credentialed B2B channels with no public page to probe.

## Path
PATH B. No ScrapeGuys API key exists in this repo, so nothing was collected. scripts/probe.py made one unauthenticated request per URL, checked robots.txt first, and stored status and timing only.

Going's postings name its fare sources as "airfare data, GDSs, NDC, metasearch, OTAs, or airline retailing" (VP of Engineering, Ashby publishedAt 2026-11-13). Going is US-based. ## Limitations
- **Not probed:** a dated search-results or booking-flow page for a specific itinerary. That page holds the "still bookable at this price" answer. It is generated per query, and no public, robots-permitted URL for it was found. GDS (Sabre, Amadeus, Travelport) and airline NDC APIs were not probed either: they need commercial credentials, so the public-sources rule rules them out.
- **Sources measured:** 7 URLs across 6 hosts, on 1 route, in 1 run.
- **Naive client, not a hardened one:** no retries, proxies, browser rendering or session handling were tried, by design. This shows where a naive attempt stops. It does not show whether a hardened collector would succeed.

## What this shows about collecting it in house
The pages a plain client can reach are the marketing layer: cached "from" fares on route pages. The layer that answers Going's question is either refused (Expedia 429), off-limits under robots (Google Flights), or behind credentials (GDS, NDC). Rechecking every alert before members act on it would mean running live, dated searches across those sources at alert volume. A naive client does not get there. The number of alerts Going sends per day is UNVERIFIED.
