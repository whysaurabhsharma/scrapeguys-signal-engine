INTERVIEW PROJECT · NOT AFFILIATED WITH SCRAPEGUYS · PRIVATE REPO

A machine that finds who needs live web data this week, and proves it.

The ScrapeGuys signal engine looks for companies with public, dated evidence that they need live web data. It scores them with deterministic Python, then drafts a sourced brief and a data asset for the best ones. It drafts and a human sends. It was built to answer a Growth Manager job description that says inbound is being built from zero.

The design decision

Architecture: the model judges, Python decides

The idea the repo rests on: anything that has to be exact or reproducible is taken away from the model. The model never scores, never assigns an id, never writes a pipeline CSV.

Model does judgment

  • Finding candidates and reading evidence
  • Deciding whether a company is a buyer or a vendor
  • Writing why_live_data: one sentence on what they cannot see
  • Writing briefs, assets, partner strategy, reports
  • Proposing weight changes, then waiting

Python does anything exact

  • Ids: ac_ + sha256(domain)[:10]; sg_ + sha256(account|type|url|ref)[:10]
  • Schema validation, rejection with a printed reason
  • Idempotent merge: re-ingesting changes nothing
  • Scoring, decay, rounding (half-up, once), tiers
  • Probing URLs politely and logging measurements

CLAUDE.md

The seven operating rules

  1. Never send. No email, DM, form post or CRM send. Every draft is a file marked DRAFT - NOT SENT. No send credential exists in the repo.
  2. Public sources only. Behind a login means it does not exist. Respect robots.txt. Documented public APIs are fine.
  3. No claim without a URL. Unsourced means UNVERIFIED or not written. An empty field beats a guessed one.
  4. No date, no signal. signal_date is when the event happened, never today. Undated signals are dropped, not estimated.
  5. Scripts write the CSVs. JSON goes to data/staging/; ingest.py does the rest.
  6. Never score by hand. If the ranking is wrong, the weights are wrong: propose, wait, re-run.
  7. Human-facing output: finding first, method second, nothing over 200 words.

Disqualify: vendors

Scraping, proxy and extraction vendors. They hire scraping engineers because it is their product, not their pain.

Disqualify: suppress list

16 domains: ScrapeGuys itself, 13 competitors (Bright Data, Oxylabs, Zyte, Apify, Firecrawl, Grass / Wynd and others), OpenAI, ElevenLabs.

Disqualify: frontier labs

Labs and hyperscalers that crawl as core infrastructure. Narrow on purpose: having engineers is not a reason to disqualify.

Signals and triggers

Date confidence multiplier

exact × 1.00

A first-published or announcement date: Greenhouse first_published, Lever createdAt, a press dateline.

ceiling × 0.75

A machine-readable date that may be a later repost: Ashby publishedAt (last published), Workable published_on, SmartRecruiters releasedDate.

approx × 0.50

No machine field, only a date printed on a page. Never the only basis for Tier A. A machine-readable field is never approx.

scripts/score.py + common.py

Scoring model

Four parts, each capped, summed to a 0–100 score. Total and pain are rounded once (half-up, one decimal), and the tier is decided on exactly the numbers shown.

score = icp_match (≤30) + pain (≤40) + capacity (≤15) + reachability (≤15) signal value = weight × 0.5^(age_days / half_life) × date_confidence pain = sum over types of the STRONGEST signal of that type (five postings for one role are one fact)

Tier rules, applied in order; first match wins

  1. No website → reject.
  2. Domain on the suppress list (subdomains match too) → reject.
  3. Pain is zero → nurture if score ≥ 30, else reject. No pain means nurture at best.
  4. Tier B pain gate: score ≥ 50 but pain < 5 → nurture. Exposed by Plush, which reached B on fit alone (pain 2.1).
  5. Tier A needs score ≥ 70 and all of: pain ≥ 15; freshest signal ≤ 90 days; at least one evidential signal (hiring or complaint) that is itself ≤ 90 days. If any fail → B, with the failed reasons written out. The evidential gate was exposed by Henfruit, which hit A on a single funding round.
  6. Score ≥ 50 → B.
  7. Score ≥ 30 → nurture.
  8. Otherwise → reject.
Emergent property, recorded as a decision: a complaint alone can never reach Tier A. Its weight of 12 (6 if approx) is always below the Tier A pain minimum of 15, so Tier A needs a second signal type alongside a complaint.
Worked example, Lyst = 76.1. icp high 30 + capacity public 10 + named CEO 15 = 55 fit. Pain: best complaint (14 Nov, 6 days, exact) 12 × 0.5^(6/45) = 10.94; hiring (26 Oct, 25 days, ceiling) 18 × 0.5^(25/60) × 0.75 = 10.12. Pain 21.1. Total 76.1, with an evidential signal 6 days old → A.

Probe politeness rules

  • robots.txt checked before any URL on that origin; a disallow, 401/403 or unreachable file means skip
  • One exception: api.ashbyhq.com in robots_allowlist.csv
  • One request at a time, 1.5 s between requests to a host (a larger Crawl-delay wins, capped)
  • 10 s timeout, no retries, even on 403 or 429
  • Cross-host redirects not followed (skipped_redirect)
  • Body read only to classify it, then discarded

What it does not show

"usable" means the page returned content, not that a price or stock level was extracted. No retries, proxies or browsers were tried, so the probe shows where a naive attempt stops, not what a hardened collector costs. Never say a sample of the company's own data is attached.

Rule 1, enforced in layers

Never-send guardrails

The real guarantee is what the repo lacks: no send credential, and one declared MCP server (Google Sheets) that cannot send. The hook and the deny rules are defence in depth.

Layer 1 · absence

No send credential. .mcp.json declares only Sheets. Clone it anywhere and nothing in it can send.

Layer 2 · settings.json

Denies rm, curl, wget, ssh, scp, nc, git push, and Edit on the three CSVs.

Layer 3 · guard.py

PreToolUse on Bash, Write, Edit, NotebookEdit and every MCP tool. Fails closed if it crashes.

guard.py's seven rules

#Blocks
1Send attempts in Bash: mail libraries, mail -s, POST to about 30 messaging and CRM hosts (Slack, Gmail API, HubSpot, Apollo, Twilio and others)
2Write / Edit / NotebookEdit to accounts, signals or scored.csv, after resolving relative and .. paths
3Bash writes to those CSVs: redirect, tee, inline python, cp/mv/rm and PowerShell equivalents
4Network tools: curl, wget, nc, ssh, scp, Invoke-WebRequest
5Write to any path outside the repo root
6MCP tools named as send actions (send, reply, forward, post, publish) plus a denylist (create_draft, manage_marketing_email and others)
7An interpreter reading its program from stdin (pipe, <, <<)

What this does badly

Known limits

  • Tier A is 3 accounts, one per ICP, each with a written caveat.
  • Going leaves A soon. Its hiring dates are ceilings; the score falls below 70 on 2026-12-17.
  • Gramiyaa's pain evidence comes from its incumbent's content. Funding date is approx. Brief held.
  • Lyst rests on 3 Trustpilot reviews and one ceiling hiring date.
  • 32 of 74 signals lack an exact date (14 ceiling, 18 approx).
  • 183 of 287 kill rows have no source URL.
  • Searches per hunt were never logged. The funnel starts at candidates.
  • 6 of 39 accounts have no named decision maker (SEON, Vogo, Phia, RestaurantSupply.com, PlanetArt, PRISM+).
  • The weights are a guess checked against 26 labelled rows; closed-won data would calibrate them.
What building it taught

Nine lessons

  1. ATS search finds roles, not buyers. Vendor listings dominate; checking likely companies' boards worked better.
  2. Seed lists failed 3 of 4 times. Vendor case studies and founder interviews found the real commerce buyers.
  3. The ai ICP is narrower than assumed. AI assistants crawl for themselves or use platform APIs.
  4. A disclaimer is not a confession. Ludex and Zyft admitted limits but never said they cannot see something.
  5. A complaint alone can never reach Tier A. This emerged from the weights and is recorded as a decision.
  6. The first run produced 0 Tier A, and the thresholds stayed. SEON scored 56.2. A run with nothing hot is a real answer.
  7. A data-contract bug cost Lyst its tier. Ingest accepted invalid stage values; the fix moved Lyst 67.7 → 76.1, and Back Market +10 with no tier change.
  8. The hook was bypassed in practice. The never-send claim now rests on what the repo lacks.
  9. An unquoted colon in frontmatter dropped allowed-tools silently. A control that fails silently reads as one that works.

Terms

Glossary

signalA dated, sourced public event (hiring, funding, launch, complaint) tied to one account.
signal_date / captured_atWhen the event happened / when the hunt found it. Decay runs on signal_date.
evidential signalHiring or complaint: shows the pain itself. Funding and launch only show budget or activity.
ceiling dateA machine date that may be a repost, so the true first date could be earlier. Weighted × 0.75.
why_live_dataOne sentence naming what this company specifically cannot see without live data. No sentence, no account.
source_refA short id for one item inside a shared source (an ATS job id), so two postings behind one JSON endpoint get two signal ids.
incumbentA vendor the account already pays (GobbleCube, Nitro, Lighthouse, PromptCloud). The deal becomes displacement, not education.
PATH A / PATH BAsset built from collected data with an API key / documented gap from the probe when there is no key. This repo only uses B.
AGED vs SCORERWhy a golden buyer misses A/B: its signals decayed (AGED) or the scorer misjudged it (SCORER). All 4 misses are AGED.
DRAFT - NOT SENTRequired on line 2 of every brief. A human decides whether anything is sent.
